# janus信令与udp通道流程
1. 建立好websocket通信通道准备通信
2. 客户端发送create消息给服务端并等待janus服务端发送回复
3. janus回复之后,客户端发送请求janus房间插件,并等待janus回复
4. janus回复插件安装之后,客户端发送请求进入房间请求,等待janus回复
5. janus回复之后,通过信号与槽调用call_session中的onJoinedAsPublisher槽函数表示进入这个房间,准备接下来的peerconnection,视频音频轨道的建立以及sdp和ice的发送
6. call_session::onJoinedAsPublisher首先创建音频源和视频源,并创建相应的视频轨道和音频轨道,创建轨道需要使用全局的XRtcGlobal::instance().GetOrCreatePeerConnectionFactory()方法获得工厂方法,这个工厂在创建的时候提供了音频编解码和视频编解码,为以后的sdp提供数据
7. call_session::onJoinedAsPublisher其次调用createPublisherPc函数创建Peerconnection对象,这个对象就是负责将视频和音频发送给janus的对象,创建这个对象的时候调用它的init函数将ice需要的stun服务器ip地址传进去了,为以后的ice发送提供数据,并将视频轨道和音频轨道连接上去,调用CreateOffer函数,这个函数开始创建本地的sdp信息,并将它设置为本地的sdp,设置本地sdp的时候开始调用PeerConnectionHandler::OnIceCandidate函数,这个函数是override的,它的调用是webrtc内部调用的,调用这个函数表示将收集的ice发送给janus,这个函数回调用多次,此时也是客户端询问stun获得本地nat地址的时候
8. 这里的sdp和ice基本上是同步的,我们先讲sdp,服务端接收到客户端的sdp之后设置它的远程sdp之后发送它自己的sdp给客户端,客户段收到这个消息为event,并通过信号与槽在call_session调用CallSession::onPublisherAnswer,这个函数中调用PeerConnectionHandler::SetRemoteDescription,表示客户端将janus发送的sdp设置为远程sdp
9. 这里是ice过程,与sdp同步进行,首先等待janus回复客户端消息,这个消息就是ice的回复消息,当ice信息被客户端接收到了,客户端将这个信息设置为远处的ice candidate,之后客户端就可以开始打洞了,开始打洞的判断和打洞都是webrtc内部进行的
10. 开始打洞了,此时客户端和服务端双方都有自己和对方的sdp,且至少有一个candidate之后开始打洞,这是webrtc内部完成的,当前的打洞都是客户端先开启的(虽然原则上双方都可以先开启,当前的方式是sfu,使用janus服务器,我们知道janus服务器的网地址,当使用p2p的时候,打洞一般都是双方同时开始的)我们是客户端先发送打洞请求,首先我们需要知道janus发送给我的ice是什么,janus发送给我们的ice就是我们需要发送的目标地址,为什么需要知道这些?我们不是知道janus 的公网ip了嘛,首先,我们知道的公网ip不是udp的地址,而是信令的地址,其次,如果是p2p格式的,我们不知道对方的地址. 客户端会测试多条连接,本地地址连所有janus发的ice地址,turn也是如此,(janus并不是完全不主动发送也会主动发送打洞请求的)当客户端收到janus回复的信息表示这条通道已经打洞成功呢了,之后会和janus确认同一条通道
